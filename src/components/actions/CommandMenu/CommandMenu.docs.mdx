# CommandMenu

A searchable, keyboard-first surface for finding and executing application commands or opening navigation destinations. CommandMenu renders the searchable menu content; wrap it in `CommandMenu.Trigger` for a button-anchored popover or place it in a `Dialog` for a global command palette.

## When to use

- Users need to search a large or changing set of application commands
- Choosing an item executes a command or opens a destination
- Keyboard-first discovery, aliases (`keywords`), and shortcut hints are important
- A trigger-based command popover or modal global command palette is needed

Choose a different component when the interaction has another outcome:

- Use [Menu](/docs/actions-menu--docs) with `MenuTrigger` for a short contextual action list that does not need a search field.
- Use [SearchComboBox](/docs/forms-searchcombobox--docs) for a focused single-line search-and-act input that may submit raw text and clears after each result.
- Use [FilterPicker](/docs/forms-filterpicker--docs) when users are searching to keep one or more selected field values.
- Use [CommandTextArea](/docs/forms-commandtextarea--docs) when a command or mention should be inserted into multiline text rather than executed immediately.

## Properties

- **`searchPlaceholder`** `string` (default: `'Search commands...'`) — Placeholder text for the search input
- **`searchValue`** `string` — The search value in controlled mode
- **`onSearchChange`** `(value: string) => void` — Callback fired when search value changes
- **`filter`** `(textValue: string, inputValue: string) => boolean` — Custom filter function for search
- **`emptyLabel`** `ReactNode` (default: `'No commands found'`) — Label to show when no results are found
- **`searchInputStyles`** `Styles` — Custom styles for the search input
- **`isLoading`** `boolean` (default: `false`) — Whether the command menu is loading
- **`shouldFilter`** `boolean` (default: `true`) — Whether to filter items based on search
- **`selectionMode`** `'none' | 'single' | 'multiple'` (default: `'none'`) — Selection mode for the command menu

- **`disabledKeys`** `Iterable<Key>` — Keys of items that should be disabled
- **`onAction`** `(key: Key) => void` — Callback fired when an item is activated, after its own `onAction()`
- **`isDisabled`** `boolean` — Whether the command menu is disabled
- **`header`** `ReactNode` — Optional header content above the search input
- **`footer`** `ReactNode` — Optional footer content below the menu
- **`menuStyles`** `Styles` — Custom styles for the menu list container
- **`itemStyles`** `Styles` — Custom styles for individual menu items
- **`sectionStyles`** `Styles` — Custom styles for section wrapper elements

## Sub-components

### CommandMenu.Item

Individual menu items within the CommandMenu. Each item is rendered using [Item](/docs/content-item--docs) and supports all Item properties for layout, icons, descriptions, and interactive features.

For detailed information about all available item properties, see the [Menu.Item documentation](/docs/actions-menu--docs#sub-components) which provides the complete API reference. Key properties include:

- **`key`** `Key` — Unique identifier for the item (required)
- **`children`** `ReactNode` — The main content/label for the menu item
- **`icon`** `ReactNode` — Icon displayed before the content
- **`rightIcon`** `ReactNode` — Icon displayed after the content
- **`description`** `ReactNode` — Secondary text below the main content
- **`prefix`** `ReactNode` — Content before the main text
- **`suffix`** `ReactNode` — Content after the main text
- **`hotkeys`** `string` — Keyboard shortcut that triggers this item
- **`tooltip`** `string | boolean | object` — Tooltip configuration
- **`isDisabled`** `boolean` — Whether the item is disabled
- **`onAction`** `() => void` — Callback fired when the item is activated, before the CommandMenu's `onAction(key)`
- **`to`** `string | Path` — Application destination resolved by Root's navigation adapter; takes precedence over `href`
- **`navigationOptions`** `NavigateOptions` — Options for client navigation, such as `replace`, `state`, `relative` and `preventScrollReset`
- **`href`** `string` — Native destination when `to` is omitted
- **`target`**, **`rel`**, **`download`**, **`ping`**, **`referrerPolicy`**, **`hrefLang`** — Native anchor attributes

#### CommandMenu-specific Properties

- **`keywords`** `string[]` — Additional search terms for better discoverability
- **`forceMount`** `boolean` — Whether to always show this item regardless of search filter
- **`textValue`** `string` — Text value for search filtering (if different from children)

#### Mixed Commands and Navigation

The same searchable collection can contain commands and links. Give commands an `onAction` and navigation destinations a `to` or `href`; do not navigate again in the action callback. CommandMenu.Item uses the same navigation behavior as [Menu.Item](/docs/actions-menu--docs#navigation-items): ordinary activation uses Root's navigation adapter, while modified clicks, middle clicks, downloads, external destinations and other targets retain native browser behavior. A `!` prefix on `to` opens a new tab, and an `@` prefix forces native navigation.

```tsx
<CommandMenu aria-label="Workbooks" onAction={recordActivation}>
  <CommandMenu.Item key="create" onAction={createWorkbook} keywords={['new']}>
    Create workbook
  </CommandMenu.Item>
  <CommandMenu.Section title="Recent workbooks">
    <CommandMenu.Item
      key="saved"
      to={{ pathname: '/workbooks/saved', search: '?view=table' }}
      description="Open the saved workbook"
    >
      Saved workbook
    </CommandMenu.Item>
  </CommandMenu.Section>
  <CommandMenu.Item key="browse" to="/workbooks">Browse all</CommandMenu.Item>
</CommandMenu>
```

Filtering, Arrow keys and Enter use the same primary items for both commands and links. The item's `onAction()` runs first, then the CommandMenu's `onAction(key)`, once each. Space activates the highlighted item only while the search is empty; while typing a query, Space inserts text. Disabled items cannot activate or navigate. Selection modes select commands; navigation items open their destination without becoming selected.

Navigation items expose `menuitem` semantics without a checked state, including when other items are checkboxes or radio choices. Supply `aria-current` to identify a destination that represents the current page.

The primary native anchor exposes the menu-item semantics and destination, while the original Item row retains its layout and style slots. The primary target follows the first visible Label, Description or leading Icon; keep one of these slots visible and give icon-only items a meaningful accessible name. Follow [Menu's focus and selector migration guidance](/docs/actions-menu--docs#focus-and-selector-migration) for custom selectors. CommandMenu uses virtual focus: the search input keeps DOM focus and identifies the active primary menu item with `aria-activedescendant`, including when styling moves the primary target to another content slot. Inline actions are unsupported in this virtual-focus mode; use a separate primary item for each command or a DOM-focus Menu when independent row actions are required.

## Accessibility

### Keyboard Navigation

The CommandMenu component provides comprehensive keyboard support:

- **Search Input Focus**: The search input is automatically focused when the palette opens
- **ArrowUp/ArrowDown**: Navigate through enabled filtered items while keeping the search input focused
- **Enter**: Activate the currently highlighted command or navigation destination
- **Space**: Activate the highlighted item only when the search is empty; otherwise insert a space into the query
- **Escape**: Clear search term or close the palette
- **Tab**: Navigate between focusable elements

### Screen Reader Support

The named search input has `searchbox` semantics and controls a `menu`, rather than a listbox of form options. Its `aria-activedescendant` points to the actual highlighted menu item, including items inside sections and native navigation anchors. Generated IDs are unique per palette. A plain command retains its consumer-provided DOM `id`; keep explicit IDs non-empty and unique within the page. Empty and loading states clear references to items that are no longer rendered.

Give the palette an `aria-label` and provide a descriptive `searchPlaceholder`, which also names the search input. Screen-reader wording and virtual-focus behavior vary by reader and browser; verify the consuming application's browser/reader combination. The [WAI-ARIA active-descendant requirements](https://www.w3.org/TR/wai-aria-1.2/#aria-activedescendant) permit a searchbox to reference an item owned by its controlled menu.

### Focus Management

- Search input maintains focus during keyboard navigation
- Virtual focus pattern for menu items
- Proper focus restoration when closing

```jsx

  <Menu.Item key="copy">Copy</Menu.Item>
  <Menu.Item key="paste">Paste</Menu.Item>
  <Menu.Item key="cut">Cut</Menu.Item>
</CommandMenu>
```




### With useDialogContainer Hook

For programmatic control over the command menu dialog:

```jsx
import { useDialogContainer } from '@cube-dev/ui-kit';

function CommandMenuDialogContent({ onClose, ...args }) {
  const handleAction = (key) => {
    console.log('Action selected:', key);
    onClose();
  };

  return (
    <Dialog size="medium" isDismissable={false}>
      <CommandMenu
        width="100%"
        height="max(40x, 90vh)"
        size="medium"
        onAction={handleAction}
        {...args}
      >
        <Menu.Item key="copy" description="Copy selected text" hotkeys="Ctrl+C">
          Copy
        </Menu.Item>
        <Menu.Item key="paste" description="Paste from clipboard" hotkeys="Ctrl+V">
          Paste
        </Menu.Item>
        <Menu.Item key="cut" description="Cut selected text" hotkeys="Ctrl+X">
          Cut
        </Menu.Item>
      </CommandMenu>
    </Dialog>
  );
}

function App() {
  const dialog = useDialogContainer(CommandMenuDialogContent);

  const handleOpenDialog = () => {
    dialog.open({
      searchPlaceholder: 'Search commands...',
      autoFocus: true,
      onClose: dialog.close,
    });
  };

  return (
    <div>
      <Button onPress={handleOpenDialog}>Open Command Menu</Button>
      {dialog.rendered}
    </div>
  );
}
```

## Advanced Features

### Enhanced Search

The CommandMenu supports enhanced search capabilities:

- **Keywords**: Items can include additional keywords for better discoverability
- **Custom values**: Items can have custom search values separate from display text
- **Force mount**: Certain items can always be visible regardless of search filter
- **Custom filtering**: Override the default search algorithm with custom logic

## Best Practices

### Do's

- **Provide clear placeholders**: Use descriptive placeholder text that indicates what users can search for
- **Use keywords**: Add relevant keywords to items for better discoverability
- **Group related commands**: Use sections to organize commands logically
- **Handle loading states**: Show loading indicators for async operations
- **Provide keyboard shortcuts**: Include hotkey hints in menu items when applicable

### Don'ts

- **Don't overload with options**: Too many commands can overwhelm users even with search
- **Don't use for simple menus**: Use regular Menu component for small, static option sets
- **Don't ignore empty states**: Always provide helpful empty state messages
- **Don't disable search**: The search functionality is core to the component's purpose

## Technical Notes

### Performance

- The component uses efficient filtering with React Stately's collection system
- Filtering updates as the search value changes
- Virtual focus keeps the search input focused during item navigation

### Browser Support

- Modern browsers with ES2018+ support
- Requires React and React DOM 19.3 or newer
- Uses React Aria for cross-browser accessibility
