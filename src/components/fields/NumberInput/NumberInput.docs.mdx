# NumberInput

A number input component that allows users to enter numeric values and increment or decrement them using stepper buttons. Built with React Aria's `useNumberField` for accessibility and the Cube `tasty` style system for theming.

## When to Use

- Collect numeric input (quantities, prices, ages, etc.)
- Allow users to increment/decrement values with stepper controls
- Enforce min/max/step constraints on numbers
- Build forms with validation and field decoration
- Support both controlled and uncontrolled usage

### Properties

- **`value`** `number | null` — The numeric value in controlled mode. `null` clears the field and keeps it controlled
- **`defaultValue`** `number` — The default numeric value in uncontrolled mode
- **`placeholder`** `string` — Placeholder text when input is empty
- **`icon`** `ReactElement` — Icon element rendered before the input
- **`prefix`** — Input decoration before the main input
- **`suffix`** — Input decoration after the main input
- **`tooltip`** `string | TooltipProviderProps` — The input's own tooltip, opened on hover over the field box and on keyboard focus. A disabled input with a tooltip stays focusable, so the keyboard reaches it too. See [TextInput](/docs/forms-textinput--docs#with-a-tooltip) for the behaviour. A disabled number input with a tooltip doesn't step from the keys, the wheel or the steppers
- **`suffixPosition`** `'before' | 'after'` (default: `before`) — Position of `suffix` relative to the stepper buttons. `before` keeps a unit next to the number (`40 px ⌃⌄`); `after` places the suffix after the steppers. The validation/loading icon always comes before both
- **`actions`** `ReactNode` — Controls placed last, after the steppers and `suffix` whatever `suffixPosition` is
- **`hideStepper`** `boolean` (default: `false`) — Whether to hide the stepper buttons
- **`minValue`** `number` — Minimum allowed value
- **`maxValue`** `number` — Maximum allowed value
- **`step`** `number` — Amount to increment or decrement the value
- **`formatOptions`** `Intl.NumberFormatOptions` — Options for formatting the displayed number value
- **`size`** `'small' | 'medium' | 'large'` (default: `medium`) — Input size
- **`autoComplete`** `string` (default: `off`) — HTML [`autocomplete`](https://developer.mozilla.org/en-US/docs/Web/HTML/Attributes/autocomplete) token that tells the browser what to autofill (`cc-number`, `one-time-code`, …). A number field opts out of autofill by default.
- **`isWheelDisabled`** `boolean` — Whether scrolling the mouse wheel changes the value
- **`decrementAriaLabel`** `string` — Custom aria-label for the decrement button, in place of the translated "Decrease {label}"
- **`incrementAriaLabel`** `string` — Custom aria-label for the increment button, in place of the translated "Increase {label}"
- **`inputProps`** `Props` — Direct props passed to the native input element, merged over the props React Aria generates: a key you set wins, and event handlers are chained rather than replaced
- **`wrapperProps`** `Props` — Direct props passed to the input wrapper element, merged with the `group` props React Aria puts there: event handlers are chained
- **`validate`** `(value: number) => ValidationError | true | null | undefined` — Client-side validation. React Aria sets `aria-invalid` from the returned errors at once; the invalid style and the message follow after the user edits or leaves the field, so an empty field does not open in red. A typed number is checked once it commits, on blur or `Enter`. An explicit `errorMessage` replaces the returned message, and an explicit `isInvalid` (or a form's validation) takes over from `validate` entirely
- **`onChange`** `(value: number) => void` — Callback fired when a new value is committed, not on each keystroke: when the field loses focus or `Enter` is pressed after typing, and at once when a stepper button, the mouse wheel or one of the keys in [Keyboard Events](#keyboard-events) changes it. Committing an empty field passes `NaN`
- **`onBlur`** `function` — Callback fired when the input loses focus
- **`onFocus`** `function` — Callback fired when the input receives focus
- **`onKeyDown`** `(e: KeyboardEvent) => void` — Callback fired when a key is pressed in the input. See [Keyboard Events](#keyboard-events)
- **`onKeyUp`** `(e: KeyboardEvent) => void` — Callback fired when a key is released in the input

#### Keyboard Events

`onKeyDown` and `onKeyUp` are attached to the `<input>` by React Aria's `useNumberField`, which handles some keys itself and runs that handling **before** your `onKeyDown`:

- `ArrowUp` / `ArrowDown` and `PageUp` / `PageDown` step the value, unless a modifier key is held
- `Home` / `End` set the value to `minValue` / `maxValue`, when those are set
- `Enter` commits the typed number, firing `onChange` when the value changed

Because they run first, `e.preventDefault()` in `onKeyDown` cannot cancel them: it cancels what the browser would do with the key, such as submitting a surrounding form on `Enter`, and keeps an `Escape` or `Tab` at the input (below). That makes NumberInput the exception among the fields with built-in key handling (`ComboBox`, `SearchComboBox`, `TagInput` and `CommandTextArea` run your handler first and skip their own handling for a key you prevent), and it is what makes an `Enter` handler work here: by the time it runs, the typed number is committed and any `onChange` for it has fired.

```jsx
<NumberInput
  label="Limit"
  onChange={setLimit}
  onKeyDown={(e) => {
    // `onChange` has already been called with the committed number.
    if (e.key === 'Enter') onCommit();
  }}
/>
```

The handler receives React Aria's keyboard event rather than a plain React one. Keys other than `Enter` continue to ancestors as usual; `Enter` stops at the input unless you call `e.continuePropagation()`. As in every field, an `Escape` or `Tab` your handler prevents stays at the input, so a surrounding `Dialog` neither closes nor moves focus on it.

## Examples

### Basic Usage

```jsx
<NumberInput label="Quantity" placeholder="Enter a number" />
```

### With Stepper Hidden

```jsx
<NumberInput label="Amount" hideStepper />
```

### With a Unit Suffix

A unit sits between the number and the steppers. Pass `suffixPosition="after"` to put the suffix after the steppers instead.

```jsx
<NumberInput label="Width" defaultValue={40} suffix={<Text>px</Text>} />
```

### With Min/Max/Step

```jsx
<NumberInput label="Age" minValue={0} maxValue={120} step={1} />
```

### With Validation

```jsx
<NumberInput
  label="Price"
  isInvalid
  errorMessage="Price must be positive"
/>
```

## Accessibility

### Keyboard Navigation

- `Tab` – Moves focus to the input field
- `Shift + Tab` – Moves focus away from the input
- Arrow keys – Increment/decrement value
- `PageUp`/`PageDown` – Increment/decrement value
- `Home`/`End` – Set to min/max value
- `Enter` – Commits the typed value
- Standard text editing shortcuts

### Screen Reader Support

- Announces a text field described as "Number field", with its label, description and validation messages
- The stepper buttons are named after the field ("Increase Quantity", "Decrease Quantity"), translated with the UI Kit locale. With a label that is not text, the name is "Increase" or "Decrease" and the label is read after it. They are not in the `Tab` order, and pressing one does not close a popover the field sits in
- State changes like "invalid" or "required" are announced
- The loading indicator is visual only: `isLoading` is not announced

### ARIA Properties

- `aria-label`, `aria-labelledby` – Accessible name for the input
- `aria-describedby` – Links to description and error messages
- `aria-invalid` – Managed automatically based on `isInvalid` and `validate`
- `aria-required` – Set when `isRequired` is true
- Additional ARIA attributes supported by React Aria's `useNumberField`

## Best Practices

1. **Do**: Provide clear labels and helpful placeholder text

   ```jsx
   <NumberInput label="Quantity" placeholder="0" />
   ```

2. **Don't**: Use placeholder text as the only label

   ```jsx
   {/* Avoid this */}
   <NumberInput placeholder="Enter a number" />
   ```

3. **Accessibility**: Always provide proper labels for screen readers
4. **Validation**: Use `isInvalid` / `isValid` and `errorMessage` for user feedback
5. **Performance**: Use `defaultValue` for uncontrolled inputs when possible

## Integration with Forms

This component supports all [Field properties](/docs/getting-started-field-properties--docs) when used within a Form.

When the browser submits the form itself (a plain `<form>`, or a Form with `action`), `name` submits the number through a hidden input: `1234.5`, not the formatted `1,234.5` the input shows. An empty field submits an empty string, and a disabled NumberInput submits nothing.
