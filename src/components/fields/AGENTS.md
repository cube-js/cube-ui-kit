## Nullable form models

`FieldBaseProps<Value>` describes what a field binding accepts, including `null | undefined` when supported; it does not describe only what the control emits on change. Preserve nullable API values in the store and normalize them only for display. Coverage lives in `Form/modern/nullable.test.tsx` under `src/components/form/` and `typecheck/consumer/modern-form-nullable.tsx`.

## Textarea autosize

`TextArea` and `CommandTextArea` share [`TextInput/useAutoSizeTextArea.ts`](TextInput/useAutoSizeTextArea.ts). It measures an off-screen mirror on purpose: **never size a live textarea by mutating its own height** (`height: auto` → read `scrollHeight` → restore). That re-lays out every ancestor mid-keystroke, and a scroll container sharing the column then has its scroll offset moved and imperfectly restored by the browser's scroll anchoring — the chat-input jitter of CUB-4042. Note also that `height: auto` sizes a textarea from its `rows` attribute and the font's line box, not from CSS `line-height`, so a `scrollHeight` read that way carries a floor and cannot report a shrink.

## Virtualized ListBox measurement

A picker's popover sizes to its options (`popover-width.ts`), so a virtualized row must give its width to the list. ListBox and Tree stack their rendered rows in one grid cell and move each down with a transform; never place them absolutely, which takes them out of the popover's `max-content` and holds it at its `30x` floor. The virtualizer also keeps the rows with the longest text rendered (`rangeExtractor`), and the widest width the list has had is held as the preferred width of an empty spacer with a `100%` floor and cap, so the popover neither jumps on scroll nor narrows on filter (`shared/virtual-width.ts`). Hold it that way, not as a `min-width` with a percentage, which counts as zero for a `max-content` size. Hold it on an element that outlives the rows: ListBox's scroll element, as a reorderable list swaps its `ul` when a search starts, and FilterTree's list, as a search that matches nothing replaces the tree. Keep it off the virtual height spacer: before the first measure it is zero, and a zero-width spacer adds no scroll height. See `popover-width.browser.test.tsx`.

A flat `ListBox` positions its options from heights react-virtual has measured, and from an estimate until it has. Never hand `measureElement` to `useCombinedRefs`, which assigns refs in a passive effect: the browser can then paint a stale height, so an option taller than its estimate, or one that just grew, overlaps the next for a frame. Options call it from a layout effect, so the correction is a sync re-render before paint. And never call `measure()` when the items change: the size cache is keyed by item key, and `measure()` drops all of it, so every option is laid out at its estimate and measured again, and the ones out of view keep the estimate. A spec for this has to run with `IS_REACT_ACT_ENVIRONMENT` off and update from a timer, because `act()` flushes effects at once and hides it. See `ListBox.browser.test.tsx` → "virtualized option heights".

The virtualizer works in the list's coordinates, not the scroll element's: its `observeElementOffset` and `scrollToFn` move the offset by the list's top offset (its margin) at the DOM. So `scrollToIndex` lands exactly, which matters when nothing else corrects it, as with End from FilterListBox's search input. Read that offset from layout (`offsetTop`), never from client rects: a scaled ancestor (a popover's opening animation, a zoomed page) scales rects but not `scrollTop`, and the virtualizer then renders the wrong window. Offset 0 is the scroll element's top in both directions, so the list's margin shows above the first option and react-virtual's re-check matches. Don't add `scrollMargin` on top, and don't correct a `scrollToIndex` afterwards: react-virtual re-checks its target for a few frames, scrolls back and warns. Import the two helpers from `@tanstack/react-virtual`, which re-exports virtual-core, so a consumer gets them from the same copy as the virtualizer. `@tanstack/virtual-core` is a devDependency only so `tsc` can follow that re-export under `preserveSymlinks`: keep it at the exact version `@tanstack/react-virtual` pins. See "ListBox focus outside the rendered window" → "from a search input".

The load-more sentinel (`onLoadMore`, `hasMore`) sits at the end of the last row (`top: $list-virtual-height` when virtualized), so a last option scrolled into view brings it into range at any `loadMoreMargin`. Specs stub `IntersectionObserver` (jsdom has none; without one the list loads nothing and doesn't throw).

## File selection state

FileInput owns native file selection separately from its model value. A controlled replacement/reset must clear obsolete native files as well as update the visible filename; browsers cannot restore file bytes from a string. Text uploads need the model value for reset synchronization too. Abort a pending FileReader when replaced or unmounted. Cover controlled, uncontrolled, and both form backends when changing this adapter.
