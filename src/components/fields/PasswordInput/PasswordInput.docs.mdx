# PasswordInput

A password input is a specialized text field that masks user input to protect sensitive information like passwords, PINs, or security codes. It includes a toggle button to reveal or hide the password text for user convenience.

## When to Use

- Collect passwords, PINs, or other sensitive text data
- Provide secure input fields in login and registration forms
- Enable password creation with visibility toggle for verification
- Collect security codes or tokens that should be masked by default
- Offer accessible password entry with reveal functionality

### Properties

- **`value`** `string | null` — The password value in controlled mode. `null` clears the field and keeps it controlled
- **`defaultValue`** `string` — The default password value in uncontrolled mode
- **`isBuffered`** `boolean` (default: `true`) — Whether typed text is held locally until the controlled `value` catches up. This is what keeps the caret in place when the value round-trips through a store that re-renders a pass late; `onChange` still fires on every keystroke. Set to `false` for a caller that must see the field snap back to its own `value` the moment it declines a keystroke.
- **`placeholder`** `string` — Placeholder text when input is empty
- **`icon`** — Icon element rendered before the input
- **`prefix`** — Input decoration before the main input
- **`suffix`** — Input decoration after the main input (before toggle button)
- **`tooltip`** `string | TooltipProviderProps` — The input's own tooltip, opened on hover over the field box and on keyboard focus. A disabled input with a tooltip stays focusable, so the keyboard reaches it too. See [TextInput](/docs/forms-textinput--docs#with-a-tooltip) for the behaviour.
- **`suffixPosition`** `'before' | 'after'` (default: `after`) — Position of suffix relative to validation/loading icons
- **`size`** `'small' | 'medium' | 'large'` (default: `medium`) — Input size
- **`shape`** `'default' | 'plain'` (default: `default`) — Shape of the field box. `plain` is square with no border at rest, for a field set flush in a container that draws its edges, such as a toolbar or a panel header. Its border keeps its width and shows on focus and in a valid or invalid state, so nothing shifts
- **`multiLine`** `boolean` (default: `false`) — Whether the field is a multiline textarea, for a secret with line breaks such as a PEM private key or a certificate. A font masks its text while it holds a value; the toggle shows it, as on a single-line field
- **`rows`** `number` (default: `1`) — The number of visible rows of a `multiLine` field
- **`autoComplete`** `string` — HTML [`autocomplete`](https://developer.mozilla.org/en-US/docs/Web/HTML/Attributes/autocomplete) token that tells the browser what to autofill (`current-password`, `new-password`, `off`, …). The lowercase `autocomplete` alias is deprecated.
- **`spellCheck`** `string` (default: `'false'`) — Whether the browser may spellcheck the value: `'true'` or `'false'`. Off by default because a browser skips only a masked single-line input, so a shown password or a multiline one would be checked, and an enhanced spellchecker could send it to its vendor
- **`autoCorrect`** `string` (default: `'off'`) — Whether the browser may autocorrect the value: `'on'` or `'off'`. Off by default for the same reason. The input's `autocapitalize` attribute is `none` too; to change it, pass `autoCapitalize` in `inputProps`, which overrides any of the three
- **`ignorePasswordManagers`** `boolean` (default: `false`) — Whether password manager extensions should leave the field alone: for a secret that is not the user's own login, such as an API key or an OAuth client secret. See [A Secret That Is Not a Login](#a-secret-that-is-not-a-login)
- **`inputProps`** `Props` — Direct props passed to the native input element, merged over the props React Aria generates: a key you set wins, and event handlers are chained rather than replaced. The explicit `isDisabled`, `maxLength`, `minLength`, `autoFocus` and `autoComplete` props win over the same attributes in `inputProps` when they are set; one left unset keeps the `inputProps` value
- **`wrapperProps`** `Props` — Direct props passed to the input wrapper element
- **`onChange`** `function` — Callback fired when the input value changes
- **`onBlur`** `function` — Callback fired when the input loses focus
- **`onFocus`** `function` — Callback fired when the input receives focus
- **`onKeyDown`** `(e: KeyboardEvent) => void` — Callback fired when a key is pressed in the input. See [Keyboard Events](#keyboard-events)
- **`onKeyUp`** `(e: KeyboardEvent) => void` — Callback fired when a key is released in the input

#### Keyboard Events

`onKeyDown` and `onKeyUp` are attached to the `<input>` by React Aria's `useTextField`. PasswordInput has no key handling of its own, so the handler simply receives the event: `e.preventDefault()` cancels what the browser would do with the key, such as typing the character or submitting a surrounding form on `Enter`. The visibility toggle is a separate button and never sees the input's keys.

The handler receives React Aria's keyboard event rather than a plain React one, and once you pass `onKeyDown` React Aria stops the key's propagation after your handler: a parent's `onKeyDown` no longer sees it. Call `e.continuePropagation()` for the keys that should travel on.

`Escape` and `Tab` are the exception, as in every field: they go on to ancestors, so a surrounding `Dialog` still closes on `Escape` and moves focus on `Tab`. When your handler acts on one, call `e.preventDefault()` and it stays at the input. To sign in on `Enter`:

```jsx
<PasswordInput
  label="Password"
  onKeyDown={(e) => {
    if (e.key === 'Enter') {
      e.preventDefault(); // keep a surrounding form from submitting
      signIn();
    }
  }}
/>
```

The fields that do handle keys themselves (`ComboBox`, `SearchComboBox`, `TagInput`, `CommandTextArea`) run your `onKeyDown` first and skip their own handling for a key you prevent. `NumberInput` is the exception: React Aria runs its stepping and `Enter` commit before your handler. In all of them, a prevented `Escape` or `Tab` stays at the input.

### A Secret That Is Not a Login

An API key, an OAuth client secret or a database password is a secret, but not one the user signs in with. Password manager extensions still read a text field followed by a password field as a login form and ignore `autocomplete="off"` there, so they offer to fill the user's own login into it or to save the secret as one. `ignorePasswordManagers` sets the attributes these extensions read as an opt-out, and each documents its own effect: `data-1p-ignore` (1Password neither saves nor fills the field), `data-lpignore` (LastPass shows no icon in it), `data-form-type="other"` (Dashlane doesn't autofill it) and `data-protonpass-ignore` (Proton Pass skips it). It also sets `data-bwignore`, but Bitwarden's release builds don't honour it today, so the flag can't keep Bitwarden away. A browser's built-in password manager (Chrome, Edge, Safari, Firefox) documents no such opt-out and may still offer to save. Set the flag on the paired text field too, so those extensions leave it alone as well.

```jsx
<TextInput label="Client ID" ignorePasswordManagers />
<PasswordInput label="Client secret" ignorePasswordManagers />
```

The same attribute set in `inputProps` wins over the flag. To drop one, pass `null` for it: Proton Pass reads its attribute by presence, so a value such as `'false'` still opts out, and `undefined` leaves the flag's value in place.

## Accessibility

### Keyboard Navigation

- `Tab` - Moves focus to the password input, then to the toggle button, which comes after it
- `Shift + Tab` - Moves focus from the toggle button back to the input
- `Enter` - Toggles password visibility when toggle button is focused
- `Space` - Toggles password visibility when toggle button is focused
- All standard text input keyboard shortcuts work for text entry

### Screen Reader Support

- A single-line field announces as a password field
- A `multiLine` field is a textarea masked by a font, so a screen reader announces it as a textbox, not a password field, and reads its text: the masking is visual only
- The toggle is a toggle button named "Show password" (translated with the UI Kit locale). Its name stays the same, and `aria-pressed` reports whether the password is shown: "Show password, pressed" while it is visible, "Show password, not pressed" while it is masked
- Validation errors and requirements are announced

### ARIA Properties

- `aria-label` - Provides accessible label when no visible label exists
- `aria-labelledby` - References external label elements
- `aria-describedby` - References additional descriptive text
- `aria-invalid` - Indicates validation state
- `aria-required` - Indicates if password entry is required
- The toggle button has `aria-label="Show password"` and `aria-pressed`, `true` while the password is shown

## Best Practices

1. **Do**: Provide clear password requirements and feedback

   ```jsx
   <PasswordInput
     label="New Password"
     description="8+ characters, including numbers and symbols"
     isValid={isValid}
     isInvalid={!isValid}
   />
   ```

2. **Don't**: Use password input for non-sensitive data

   ```jsx
   <PasswordInput label="Username" /> {/* Use TextInput instead */}
   ```

3. **Security**: Always use HTTPS when handling password inputs
4. **Validation**: Provide real-time validation feedback for password creation
5. **Accessibility**: Ensure toggle button is easily accessible via keyboard
6. **UX**: Include the visibility toggle for better user experience
