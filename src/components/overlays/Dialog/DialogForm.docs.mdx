# DialogForm

DialogForm combines a dialog, a form, and submit/cancel actions. It closes after a successful submission and keeps the dialog open when validation or saving fails.

## Choose the implementation

UI Kit has two form implementations. **Use the modern controller API for new forms.** Pass `form={Form.useController<Model>()}` to select it. `DialogForm` without a modern controller continues to use the legacy implementation, including existing `Form.useForm()` callers. The same input components work with either implementation.

The examples below use modern controllers. See [Modern Form](/docs/forms-modernform--docs) for defaults, nullable API values, subscriptions, validation, and submission recipes. The [migration guide](https://github.com/cube-js/cube-ui-kit/blob/main/docs/modern-form-migration.md) explains differences from legacy forms.

## When to Use

- Collect input in a focused dialog, such as creating or editing a record
- Confirm an operation that needs validated input
- Close automatically after saving, with built-in loading and cancel actions

## Properties

- **`form`** `FormController<T> | CubeFormInstance<T>` — Modern controller (recommended) or legacy instance. Omitting it selects legacy behavior.
- **`title`** `string` — Dialog title
- **`danger`** `boolean` — Give the submit button the danger theme
- **`submitProps`** `CubeButtonProps` (legacy) / `Omit<CubeSubmitButtonProps<T>, 'form'>` (modern) — Customize the submit button, including its label and modern `disableOnInvalid`
- **`cancelProps`** `CubeButtonProps` — Customize the cancel button, including its label
- **`preserve`** `boolean` (default: `false`) — Retain values when the editing session ends. Keep the controller mounted above the dialog to retain a draft across dialog unmounts.
- **`noActions`** `boolean` — Hide the default submit/cancel buttons
- **`children`** `ReactNode | ((dismiss: () => void) => ReactNode)` — Fields, or a render function for custom actions
- **`onDismiss`** `() => void` — Called by the built-in Cancel/close button or the render function's `dismiss`. Handle Escape, outside clicks, and externally controlled closing on `DialogTrigger` or `DialogContainer`.
- **`onSubmit`** `(values: FormValues<T>, context: ModernSubmitContext) => void | Promise<void>` — Modern submit callback. Resolve to close; throw/reject to keep the dialog open. The context supplies an `AbortSignal`.
- **`onSubmitFailed`** `(failure: ModernSubmitFailure) => void | Promise<void>` — Distinguishes invalid fields from a failed save
- **`onValuesChange`** `(values: FormValues<T>, change: FormChange) => void | Promise<void>` — Modern value-change callback
- **`submitValues`** `'active' | 'all'` (default: `'active'`) — Modern native submission payload, including Enter. `'all'` includes retained values; validation still checks active fields.
- **`onReset`** `(event: FormEvent<HTMLFormElement>) => void` — Modern native reset interception; `preventDefault()` cancels it
- **`defaultValues`** `Partial<T>` — Legacy only. Seed modern defaults in `Form.useController()`.
- **`size`** `'S' | 'M' | 'L' | 'small' | 'medium' | 'large'` — Dialog size
- **`isDismissable`** `boolean` — Show the dialog's close affordance; configure Escape/outside-click dismissal on the container
- **`closeIcon`** `ReactElement` — Custom close icon
- **`closeButtonStyles`** `Styles` — Close button styles

Supports shared [Form presentation properties](/docs/forms-form--docs#properties), [Dialog styles](/docs/overlays-dialog--docs), and [Base properties](/docs/getting-started-base-properties--docs). Layout/style props style the dialog; label and form configuration props configure its inner form.

### Form presentation properties

- **`labelPosition`** `'top' | 'side' | 'split'` — Position field labels
- **`labelStyles`** `Styles` — Field label styles
- **`labelWidth`** `Styles['width']` — Modern inner form label width
- **`orientation`** `'vertical' | 'horizontal'` — Modern inner form orientation
- **`necessityIndicator`** `'icon' | 'label' | null` — Required/optional indicator style
- **`isReadOnly`** `boolean` — Make fields read-only
- **`isValid`** `boolean` — Show valid field styling
- **`validationState`** `'valid' | 'invalid'` — Deprecated; use `isInvalid` / `isValid`

### Style Properties

These properties allow direct style application without using the `styles` prop:

- **Base:** `display`, `font`, `preset`, `hide`, `whiteSpace`, `opacity`, `transition`
- **Dimension:** `width`, `height`, `blockSize`, `inlineSize`, `flexBasis`, `flexGrow`, `flexShrink`, `flex`
- **Block:** `border`, `blockBorder`, `inlineBorder`, `radius`, `shadow`, `outline`, `padding`, `blockPadding`, `inlinePadding`, `overflow`, `scrollbar`, `textAlign`
- **Flow:** `flow`, `place`, `placeItems`, `placeContent`, `alignItems`, `alignContent`, `justifyItems`, `justifyContent`, `align`, `justify`, `gap`, `columnGap`, `rowGap`, `gridColumns`, `gridRows`, `gridTemplate`, `gridAreas`

## Examples

### Open a form with DialogTrigger

Create the controller above the dialog. Put callbacks on `DialogForm` and bind inputs with `name`.

```tsx
import { Button, DialogForm, DialogTrigger, Form, TextInput } from '@cube-dev/ui-kit';

function EditProfile({ initialProfile, save }) {
  const form = Form.useController<{ name: string | null; email: string | null }>({
    defaultValues: initialProfile,
  });

  return (
    <DialogTrigger>
      <Button>Edit profile</Button>
      <DialogForm
        form={form}
        title="Edit profile"
        submitProps={{ label: 'Save' }}
        onSubmit={(values, { signal }) => save(values, signal)}
      >
        <TextInput name="name" label="Name" isRequired />
        <TextInput name="email" label="Email" rules={[{ type: 'email' }]} />
        <Form.SubmitError />
      </DialogForm>
    </DialogTrigger>
  );
}
```

`defaultValues` is read once. For later API data, choose `adoptDefaultValues` to preserve edits or `reset({ values })` to start a new editing session. See [loading server data](/docs/forms-modernform--docs#load-server-data-refresh-defaults-or-discard-edits).

### Programmatic opening

Use [useDialogContainer](/docs/overlays-usedialogcontainer--docs) when there is no persistent trigger. Its content component can own a fresh controller for each mount.

```tsx
function UserFormDialog({ initialData, save }) {
  const form = Form.useController({ defaultValues: initialData });
  return (
    <DialogForm form={form} title="User information" onSubmit={save}>
      <TextInput name="name" label="Name" isRequired />
      <Form.SubmitError />
    </DialogForm>
  );
}

function App() {
  const dialog = useDialogContainer(UserFormDialog);
  return (
    <>
      <Button onPress={() => dialog.open({ initialData: { name: '' }, save: saveUser })}>
        Add user
      </Button>
      {dialog.rendered}
    </>
  );
}
```

Do not call `dialog.close()` from the submit callback: `DialogForm` already closes on success. If reusing a mounted content component for another record, remount it with a record key or explicitly reset its controller.

### Custom actions and drafts

```tsx
function DraftDialog({ form, save }) {
  return (
    <DialogForm form={form} title="Edit draft" preserve noActions onSubmit={save}>
      {(dismiss) => (
        <>
          <TextInput name="title" label="Title" />
          <Form.SubmitError />
          <ButtonGroup>
            <Form.Submit>Publish</Form.Submit>
            <Button onPress={dismiss}>Keep draft and close</Button>
          </ButtonGroup>
        </>
      )}
    </DialogForm>
  );
}
```

The parent owns `form` in this example. `preserve` keeps its draft on dismissal and success; it cannot preserve a controller whose owning component is itself destroyed. It is separate from a field's `preserve` option, which controls retained values when that individual input unmounts.

## Behavior

- Modern forms use the same callback precedence as `Form`: root callbacks override controller callbacks; omitted callbacks fall back to the controller's latest committed callbacks. Automatic closing works for both, including imperative `form.submit()`.
- Invalid fields and rejected saves leave the dialog open. Include `Form.SubmitError` to display save failures. Submit stays enabled after validation errors by default so the user can retry.
- In a popover, modern form actions keep the dialog open while validating or saving. This also covers custom actions inside the form; successful submission and explicit dismissal control when it closes.
- Explicit Submit/Cancel actions can close a dialog even when its trigger disables passive dismissal with `isDismissable={false}`. Escape and outside-click dismissal remain disabled.
- Modern dismissal cancels pending submission even with `preserve`. The submitted callback receives an aborted signal; a late completion cannot close a reopened dialog. Pass the signal to abortable API work.
- Modern values reset when the editing session ends unless `preserve` is set. This includes Cancel, the close button, Escape/outside closing, and removal of the dialog. Hidden dialogs also end the session when closed. A close followed by an immediate reopen has no delayed reset that can erase new edits.
- Replacing the modern controller ends the detached controller's session using its last committed `preserve` setting. The new controller keeps its own values and editing session.
- Legacy callers retain their existing callback and reset contracts, including the delayed reset after built-in Cancel and successful submit. Refer to [FormInstance (legacy)](/docs/forms-forminstance--docs) for its methods.

## Accessibility

Provide a descriptive title and visible input labels. Tab and Shift+Tab navigate controls, Enter submits using native form behavior, and Escape dismisses when allowed by the container. Dialog manages focus containment and restoration. See [Dialog accessibility](/docs/overlays-dialog--docs#accessibility).
