# DialogContainer

A DialogContainer accepts a single Dialog as a child, and manages to show and hide it in a modal. Useful in cases where there is no trigger element or when the trigger unmounts while the dialog is open.

## When to Use

- When you need to display a dialog without a specific trigger element
- To prevent dialog closure when the trigger component unmounts
- For programmatically controlled dialogs in complex application flows
- When managing dialog state externally from the component hierarchy
- For dialogs that need to persist across route changes or component updates

---

### Properties

- **`children`** — The Dialog to display, if any
- **`type`** `'modal' | 'tray' | 'fullscreen' | 'fullscreenTakeover' | 'panel'` (default: `modal`) — The type of Dialog that should be rendered
- **`styles`** `Styles` — Styles for the overlay content shell
- **`isDismissable`** `boolean` (default: `true`) — Whether the Dialog is dismissible
- **`isKeyboardDismissDisabled`** `boolean` (default: `false`) — Whether pressing the escape key to close the dialog should be disabled
- **`isOpen`** `boolean` — Whether the modal is open or not
- **`onDismiss`** `function` — Handler called when the x button of a dismissible Dialog is clicked
- **`hideOnClose`** `boolean` (default: `false`) — Whether the dialog should be hidden when closed. Focus moves as for a dialog that mounts on open: in on every open, and on close back to the element that opened it, or to the menu's trigger when a menu item opened it. [Focus with `hideOnClose`](#focus-with-hideonclose) lists what still differs

### Base Properties

DialogContainer has no DOM root. Apply [Base properties](/docs/getting-started-base-properties--docs) to its child Dialog.

### Styling Properties

`styles` customizes the overlay content shell, matching DialogTrigger. Set the child Dialog's `styles` separately: the shell and Dialog have independent size limits. For an expandable tray, keep `type="tray"` and change both style maps; switching between tray and modal/fullscreen types replaces the overlay subtree.

### Style Properties

Set these direct style properties on the child Dialog. DialogContainer itself exposes only the `styles` map for its overlay shell:

- **Base:** `display`, `font`, `preset`, `hide`, `whiteSpace`, `opacity`, `transition`
- **Dimension:** `width`, `height`, `blockSize`, `inlineSize`, `flexBasis`, `flexGrow`, `flexShrink`, `flex`
- **Block:** `border`, `blockBorder`, `inlineBorder`, `radius`, `shadow`, `outline`, `padding`, `blockPadding`, `inlinePadding`, `overflow`, `scrollbar`, `textAlign`
- **Flow:** `flow`, `place`, `placeItems`, `placeContent`, `alignItems`, `alignContent`, `justifyItems`, `justifyContent`, `align`, `justify`, `gap`, `columnGap`, `rowGap`, `gridColumns`, `gridRows`, `gridTemplate`, `gridAreas`

## Variants

### Types

- `modal` - Standard modal dialog with backdrop (default)
- `tray` - Bottom-aligned modal tray with backdrop
- `fullscreen` - Takes up entire screen with padding
- `fullscreenTakeover` - Fullscreen without padding
- `panel` - Side panel overlay

## Examples

### Basic Usage

```jsx
<DialogContainer isOpen={isDialogOpen} onDismiss={() => setIsDialogOpen(false)}>
  <Dialog>
    <Header>
      <Title>Dialog Title</Title>
    </Header>
    <Content>
      <Paragraph>Dialog content goes here.</Paragraph>
    </Content>
  </Dialog>
</DialogContainer>
```

### Controlled Dialog

```jsx
function ControlledDialogExample() {
  const [isOpen, setIsOpen] = useState(false);

  return (
    <>
      <Button onPress={() => setIsOpen(true)}>Open Dialog</Button>
      <DialogContainer
        isOpen={isOpen}
        isDismissable
        onDismiss={() => setIsOpen(false)}
      >
        <Dialog>
          <Header>
            <Title>Controlled Dialog</Title>
          </Header>
          <Content>
            <Paragraph>This dialog is controlled externally.</Paragraph>
          </Content>
          <Footer>
            <Button onPress={() => setIsOpen(false)}>Close</Button>
          </Footer>
        </Dialog>
      </DialogContainer>
    </>
  );
}
```

### Conditional Dialog

```jsx
function ConditionalDialog() {
  const [showDialog, setShowDialog] = useState(false);
  const [dialogContent, setDialogContent] = useState(null);

  const openDialog = (content) => {
    setDialogContent(content);
    setShowDialog(true);
  };

  return (
    <DialogContainer isOpen={showDialog} onDismiss={() => setShowDialog(false)}>
      {dialogContent && (
        <Dialog>
          <Header>
            <Title>Dynamic Dialog</Title>
          </Header>
          <Content>
            {dialogContent}
          </Content>
        </Dialog>
      )}
    </DialogContainer>
  );
}
```

### Custom-size Tray

```jsx
const dimensions = { width: '(100dvw - 2x)', height: '60dvh' };

<DialogContainer
  type="tray"
  styles={dimensions}
  isOpen={isOpen}
  onDismiss={() => setIsOpen(false)}
>
  <Dialog isDismissable={false} styles={dimensions} aria-label="Chat">
    <Button onPress={() => setIsOpen(false)}>Close chat</Button>
    {/* Conversation and composer */}
  </Dialog>
</DialogContainer>
```

The Dialog's `isDismissable={false}` hides its built-in visible Close button. The container remains dismissable with Escape or an outside press. A tray is modal: its backdrop keeps the page visible but prevents interaction with it. To expand without remounting its content, keep the tray type and update both dimensions to `100dvw` / `100dvh`. Test the content with the supported mobile keyboards and short viewports; `dvh` follows the dynamic viewport, not every virtual-keyboard overlay.

### Non-dismissable Dialog

```jsx
<DialogContainer isOpen={isOpen} isDismissable={false}>
  <Dialog>
    <Header>
      <Title>Important Notice</Title>
    </Header>
    <Content>
      <Paragraph>This dialog requires user action to close.</Paragraph>
    </Content>
    <Footer>
      <Button type="primary" onPress={handleAction}>
        Take Action
      </Button>
    </Footer>
  </Dialog>
</DialogContainer>
```

## Accessibility

### Keyboard Navigation

- `Tab` - Moves focus between interactive elements within the dialog
- `Shift + Tab` - Moves focus backward between interactive elements
- `Escape` - Closes the dialog if `isDismissable` is true and `isKeyboardDismissDisabled` is false

### Screen Reader Support

- Dialog announces as "dialog" to screen readers
- Focus is trapped within the dialog when open
- Focus management is handled automatically

### Focus with `hideOnClose`

A dialog kept mounted while closed moves focus as one that mounts on open does, except:

- `autoFocus` on a `Menu`, `ListBox`, `Calendar`, `RangeCalendar` or `PeriodCalendar`, and a native `autoFocus` on an element of your own, act only when the dialog mounts, hidden. The kit's inputs, buttons, `Select` and `CommandMenu` mark themselves `data-autofocus` instead, which the dialog focuses on every open; mark an element of your own the same way
- Closing a dialog opened from a context menu's item (`useContextMenu`, `useAnchoredMenu`), or reopened from a dialog it opened (a wizard's Back step), leaves focus on the page
- Opened from inside another open modal, it takes focus only when it is rendered inside that modal's dialog; rendered elsewhere, the modal keeps focus
- Nested in another overlay, it opens above that overlay only where the browser supports `Element.moveBefore`

### ARIA Properties

- `aria-modal` - Not set. While a modal, fullscreen or tray dialog is open, the page behind it is `aria-hidden` instead, so a screen reader's reading cursor stays in the dialog. Lists, menus and popovers opened from the dialog render outside it and stay readable, which `aria-modal` would prevent. Popover and panel dialogs leave the page readable
- `aria-labelledby` - Links dialog to its title automatically
- `aria-describedby` - Links dialog to its description content
- `role` - Set to "dialog" for proper semantic meaning

## Best Practices

1. **Do**: Use DialogContainer for dialogs without specific triggers

   ```jsx
   <DialogContainer isOpen={showErrorDialog} onDismiss={clearError}>
     <Dialog>
       <Header>
         <Title>Error</Title>
       </Header>
       <Content>
         <Paragraph>{errorMessage}</Paragraph>
       </Content>
     </Dialog>
   </DialogContainer>
   ```

2. **Don't**: Use DialogContainer when DialogTrigger is more appropriate

   ```jsx
   {/* Prefer DialogTrigger when you have a specific trigger */}
   <DialogContainer isOpen={buttonPressed}>
     <Dialog>...</Dialog>
   </DialogContainer>
   ```

3. **State Management**: Always control the `isOpen` state externally
4. **Single Child**: Only pass one Dialog as a child to DialogContainer
5. **Cleanup**: Ensure proper cleanup of dialog state when component unmounts
