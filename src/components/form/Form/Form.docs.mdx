# Form

Form provides field binding, validation, submission, and shared layout. UI Kit ships **two implementations behind the same component**:

| Implementation | How to select it | When to use it |
| --- | --- | --- |
| **Modern (recommended)** | `const form = Form.useController<Model>()`, then `<Form form={form}>` | New forms and incremental migrations; typed models, narrow subscriptions, cancellable validation/submission, and React Compiler verification |
| Legacy | `Form.useForm()` or a root without a modern controller | Existing forms that have not been migrated |

All examples on this page use the modern API. Existing legacy forms continue to work. [FormInstance (legacy)](/docs/forms-forminstance--docs) and [Field (legacy)](/docs/forms-field--docs) document compatibility APIs. Follow the [migration checklist](https://github.com/cube-js/cube-ui-kit/blob/main/docs/modern-form-migration.md) when converting a form; changing the creation hook alone is not sufficient.

## Start here

```tsx
import { Form, TextInput } from '@cube-dev/ui-kit';

function EmailForm({ initialEmail, save }) {
  const form = Form.useController<{ email: string | null }>({
    defaultValues: { email: initialEmail },
  });
  return (
    <Form form={form} onSubmit={(values, { signal }) => save(values, signal)}>
      <TextInput name="email" label="Email" isRequired rules={[{ type: 'email' }]} />
      <Form.SubmitError />
      <Form.Submit>Save</Form.Submit>
      <Form.Reset>Reset</Form.Reset>
    </Form>
  );
}
```

Use `name` for ordinary bindings, including `name={['user', 'email']}` for nested data. Use an optional `field={form.field(path, options)}` descriptor for model-checked paths and inferred validator types. Modern strings are literal keys; dotted strings do not select nested data.

The [Modern Form guide](/docs/forms-modernform--docs) is the implementation reference. It covers [API choices](/docs/forms-modernform--docs#pick-one-binding-and-one-owner-for-each-concern), [reactive reads](/docs/forms-modernform--docs#read-a-value-show-status-or-reveal-a-section), [server defaults](/docs/forms-modernform--docs#load-server-data-refresh-defaults-or-discard-edits), [validation](/docs/forms-modernform--docs#validate-simple-rules-sibling-fields-or-an-api-response), [conditional fields](/docs/forms-modernform--docs#hide-fields-use-nested-data-or-build-a-wizard), [submission](/docs/forms-modernform--docs#submit-display-server-errors-and-reset), and [custom controls](/docs/forms-modernform--docs#implement-a-reusable-custom-control).

## Properties

### Form-specific Properties

- **`form`** `FormController<T> | CubeFormInstance<T>` — Controller created by `Form.useController()` (recommended), or a legacy instance. Omitting it selects legacy behavior.
- **`name`** `string` — Form name and prefix for generated field ids
- **`onSubmit`** `(values: FormValues<T>, context: ModernSubmitContext) => void | Promise<void>` — Modern save callback after successful validation; context includes an `AbortSignal`
- **`onSubmitFailed`** `(failure: ModernSubmitFailure) => void | Promise<void>` — Modern failure callback; inspect `status` for `'invalid'` or `'failed'`
- **`onValuesChange`** `(values: FormValues<T>, change: FormChange) => void | Promise<void>` — Modern change callback with source, kind, and affected names
- **`submitValues`** `'active' | 'all'` (default: `'active'`) — Modern native submission payload. Both modes validate active fields only.
- **`onReset`** `(event: FormEvent<HTMLFormElement>) => void` — Modern native reset interception; `preventDefault()` cancels the reset
- **`defaultValues`** `Partial<T>` — Legacy only. Modern defaults belong in the controller creation options; use explicit commands for later data.
- **`labelWidth`** `Styles['width']` — Label-area width with side-positioned labels
- **`orientation`** `'vertical' | 'horizontal'` (default: `'vertical'`) — Form layout

Root callbacks override controller callbacks; omitted callbacks fall back to the latest committed hook callbacks. Keep each callback in one place. Values passed to modern callbacks are readonly and potentially incomplete; map them to your API request type where necessary.

### Inherited Form Properties

These properties are inherited by all input components within the form:

- **`labelPosition`** `'top' | 'side' | 'split'` (default: `top`) — Where to place labels relative to inputs. `'top'` places labels above inputs, `'side'` places labels beside inputs with fixed width, `'split'` places labels and inputs on opposite sides without fixed label width
- **`labelStyles`** `Styles` — Styles applied to field labels
- **`requiredMark`** `boolean` (default: `true`) — Whether to show required field indicators
- **`necessityIndicator`** `'icon' | 'label' | null` (default: `icon`) — Type of necessity indicator. `null` suppresses it
- **`isReadOnly`** `boolean` (default: `false`) — Whether fields are read-only by default
- **`isInvalid`** `boolean` — Invalid state for all fields
- **`isValid`** `boolean` — Valid state for all fields
- **`validationState`** `'valid' | 'invalid'` — _(deprecated)_ Use `isInvalid` / `isValid` instead
- **`validateTrigger`** `'onBlur' | 'onChange' | 'onSubmit'` (default: `onBlur`) — When to trigger validation
- **`showValid`** `boolean` (default: `false`) — Whether to show valid state indicators

### HTML Form Properties

- **`action`** `string` — Form action URL (for server submission)
- **`autoComplete`** `string` — Browser autocomplete behavior
- **`encType`** `string` — Form encoding type
- **`method`** `'get' | 'post'` — HTTP method for form submission
- **`target`** `string` — Target for form submission

### Styling Properties

#### styles

Customizes the root form element.

The Form component does not expose styled sub-elements via the `styles` prop. It uses a simple container layout that can be customized through the main styles property.

### Style Properties

These properties allow direct style application without using the `styles` prop:

- **Base:** `display`, `font`, `preset`, `hide`, `whiteSpace`, `opacity`, `transition`
- **Position:** `gridArea`, `order`, `gridColumn`, `gridRow`, `placeSelf`, `alignSelf`, `justifySelf`, `zIndex`, `margin`, `blockMargin`, `inlineMargin`, `inset`, `blockInset`, `inlineInset`, `position`, `scrollMargin`, `blockScrollMargin`, `inlineScrollMargin`, `scrollPadding`, `blockScrollPadding`, `inlineScrollPadding`
- **Dimension:** `width`, `height`, `blockSize`, `inlineSize`, `flexBasis`, `flexGrow`, `flexShrink`, `flex`
- **Block:** `border`, `blockBorder`, `inlineBorder`, `radius`, `shadow`, `outline`, `padding`, `blockPadding`, `inlinePadding`, `overflow`, `scrollbar`, `textAlign`
- **Color:** `color`, `fill`, `fade`, `image`
- **Flow:** `flow`, `place`, `placeItems`, `placeContent`, `alignItems`, `alignContent`, `justifyItems`, `justifyContent`, `align`, `justify`, `gap`, `columnGap`, `rowGap`, `gridColumns`, `gridRows`, `gridTemplate`, `gridAreas`

### Modifiers

The `mods` property accepts the following modifiers:

- **`has-sider`** `boolean` — Applied when `labelPosition="side"`
- **`has-split`** `boolean` — Applied when `labelPosition="split"`
- **`horizontal`** `boolean` — Applied when `orientation="horizontal"`

## Examples

### Layout

```tsx
function SearchForm() {
  const form = Form.useController({ defaultValues: { query: '' } });
  return (
    <Form form={form} orientation="horizontal" labelPosition="side">
      <TextInput name="query" label="Query" />
      <Form.Submit>Search</Form.Submit>
    </Form>
  );
}
```

### Defaults and reset

```tsx
const form = Form.useController({ defaultValues: { email: 'user@example.com' } });
// In an event handler, begin a new editing session with fetched values:
form.reset({ values: { email: fetchedEmail } });
```

Defaults initialize once. `adoptDefaultValues` can apply later API data while retaining user edits; `reset({ values })` replaces the baseline and current values. See the modern guide before choosing between them.

<Canvas of={FormStories.WithDefaultValues} />

### Validation and save errors

```tsx
<Form form={form} onSubmit={save}>
  <TextInput name="email" label="Email" isRequired />
  <Form.SubmitError />
  <Form.Submit>Save</Form.Submit>
</Form>
```

A thrown/rejected save error appears through `Form.SubmitError`. Validation errors appear on their fields. Modern Submit remains enabled after validation errors by default; pass `disableOnInvalid` to opt into disabling it. Double submission is guarded while work is pending.

### Dialog forms

[DialogForm](/docs/overlays-dialogform--docs) accepts the same modern controller and handles closing after success. It also supports existing legacy callers.

```tsx
<DialogForm form={form} title="Edit profile" onSubmit={save}>
  <TextInput name="email" label="Email" />
  <Form.SubmitError />
</DialogForm>
```

A `Form` placed directly in a `Dialog`, wrapping its `Content` and `Footer`, lays itself out as the dialog's slot column: a flex column that grows into the dialog, lets `Content` scroll, and adds no space between the slots. That is the form's own state, so `styles` on the form still override it property by property. A form nested inside `Content` is an ordinary form.

## React Compiler

The modern controller, subscriptions, input binding, and dialog workflows are tested with React Compiler on React 18 and 19. The published library remains uncompiled. Consumer render code must use `Form.useValue`, `Form.useFieldState`, or selectors to subscribe; imperative getters do not subscribe. This does not make legacy mutable instance reads Compiler-safe.

## Accessibility

Use visible labels, clear validation messages, and native submit/reset buttons. Named inputs connect their labels and error messages automatically. Enter submits through the form; Tab and Shift+Tab navigate controls. Configure `isRequired` when a field needs both validation and a visible required indicator.
