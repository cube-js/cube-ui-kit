# Form System

The rules for building form-attachable input components live in [`docs/rules/input-components.md`](../../../docs/rules/input-components.md) — hook order, the two `useFieldProps` modes, id/label wiring, `wrapWithField`, validation props and the shared validation helpers.

Read it before touching anything in this folder or in `src/components/fields/`.

The current Form engine is the **legacy backend** of the Form modernization plan. Its behaviour is frozen by the characterization suite in [`Form/legacy-contract/`](Form/legacy-contract/README.md): every `it()` there is labelled `[frozen]`, `[bug-eligible]`, `[undefined]` or `[design-input]`, and the README's contract table says what each label allows. Do not change a `[frozen]` behaviour, and do not fix a `[bug-eligible]` one without a compatibility review. `pnpm diagnostics:form` reports (but does not yet enforce) the React Hooks / Compiler findings for this folder against a committed baseline.

The dual-backend shell (plan Phase 3) is in place: `Form/backend.ts` brands instances (`FORM_BACKEND`), `Form.tsx` exports the `<Form>` facade that renders `LegacyFormRoot` (the frozen engine) or the `ModernFormRoot` boundary (an error until the modern backend lands), and the root provides two contexts — the public legacy `FormContext` (presentation props plus the instance) and the backend-neutral `FormPresentationContext`. Radio/Checkbox groups mask both through the exported `FormScopeMask`; a bare `FormContext.Provider` override no longer masks presentation. `useFieldProps` calls every hook in every mode — `useField` is the legacy adapter and runs inert (`unbound`) for standalone inputs — and it is keyed on `(form, name)`, so an input may gain or lose a name or move between forms after mount; keep it that way. Shell behaviour is covered by `Form/dual-backend-shell.test.tsx`; the public type contracts live in `Form/form-types.test-d.tsx`, compiled by `pnpm test:types` (a CI step, not part of `pnpm test`).
