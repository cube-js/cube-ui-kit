# Form System

Consumer guidance lives in [`docs/modern-form-guide.md`](../../../docs/modern-form-guide.md), rendered directly by `Form/ModernForm.docs.mdx` so Storybook and packaged docs share one source. Keep recipes there and migration differences in `docs/modern-form-migration.md`; label legacy references explicitly. Use `name` for ordinary bindings and optional typed descriptors for model checking, root callbacks for UI forms, and narrow subscriptions in examples; explain alternatives by their distinct use case.

The rules for building form-attachable input components live in [`docs/rules/input-components.md`](../../../docs/rules/input-components.md) — hook order, the `useFieldProps` modes, id/label wiring, `wrapWithField`, validation props and the shared validation helpers.

Read it before touching anything in this folder or in `src/components/fields/`.

The original Form engine is the **legacy backend** of the Form modernization plan. Its behaviour is frozen by the characterization suite in [`Form/legacy-contract/`](Form/legacy-contract/README.md): every `it()` there is labelled `[frozen]`, `[bug-eligible]`, `[undefined]` or `[design-input]`, and the README's contract table says what each label allows. Do not change a `[frozen]` behaviour, and do not fix a `[bug-eligible]` one without a compatibility review. `pnpm diagnostics:form` reports (but does not yet enforce) the React Hooks / Compiler findings for this folder against a committed baseline.

The dual-backend shell (plan Phase 3) is in place. File map: `Form/backend.ts` (the `FORM_BACKEND` brand and the modern-controller guard), `Form/Form.tsx` (the `<Form>` facade, `LegacyFormRoot`, the public `FormContext` plus the backend-neutral `FormPresentationContext`, the exported `FormScopeMask`), `Form/ModernFormRoot.tsx` (the modern context/presentation root), `Form/use-field/use-field.ts` (the legacy adapter; run `unbound` for standalone inputs, it rebinds when the name changes or a form appears, and its effects depend on the name, the id base and the field object — never on the form's identity, which may change per render). Behaviour rules live in `docs/rules/input-components.md`; the shell's own tests are `Form/dual-backend-shell.test.tsx`, and the public type contracts are `Form/form-types.test-d.tsx`, compiled by `pnpm test:types` (a CI step, not part of `pnpm test`).

The modern implementation lives in `Form/modern/`; read its [contract](Form/modern/README.md) before extending it. The Phase 4 store remains framework-neutral and internal. Phase 5 adds the public controller facade, `Form.useController`, `Form.useSelector`, `Form.Subscribe`, and `Form.useControllerContext`, plus the context/presentation root. `pnpm test:form-store` runs pure store tests in Node; `pnpm test:form-react` runs the adapter/root contract against React 18 and 19 in CI. Do not dispose the hook-created controller in effect cleanup: Strict Mode and hidden trees reconnect effects while preserving controller state. Subscriptions own their cleanup. Legacy roots and `FormScopeMask` mask modern context; modern roots mask legacy context. Phase 6 adds commit-time field registration and narrow input subscriptions in `Form/use-field/use-field-binding.ts` and `Form/modern/field-binding.ts`. Named inputs support modern controllers; `Form.Item` remains legacy-only. Phase 7 implements rules, cancellation, submission, callback ownership, and reactive helpers. `pnpm test:form-compiled` runs the same modern React contract through React Compiler (including an output assertion for the submission fixture); it runs with React 18 and 19 in CI. Published library output remains uncompiled. The modern adapter must add zero compiler diagnostics.

Modern DX additions: optional `form.field(path, { validate, deps, dependsOn })` descriptors add model checking and validator inference. `Form.useValue` / `useFieldState` select immutable state. Hook business callbacks update only after commit; root overrides fall back to the latest hook callbacks. Validator reads use one snapshot and only cancel stale in-flight work; `dependsOn` declares paths for revalidation and `deps` tracks external inputs. Rule constraints and function source are compared automatically; `rulesKey` skips only function-source comparison. Descriptor construction keeps authored functions on rules for lazy comparison and leaves public `deps` unchanged. Keep descriptor construction pure and native root binding behind internal commands so compiled consumers remain safe. Regression and compiled consumer coverage lives in `modern/dx.test.tsx` / `field.fixture.tsx`; built declarations are checked by `typecheck/consumer/modern-form-dx.tsx`.

Modern tuple names use the same path keys and registration lifecycle as descriptors. Preserve the tuple until the modern binding resolves it, then expose only a string name to React Aria/DOM props. Legacy `Field`/`useField` remain string-only; the shared binding rejects tuples on legacy controllers. Keep published input declarations compatible with tuple names by overriding native Aria `name` types, and cover both contexts and explicit controllers in consumer fixtures.

`Form/modern/input-workflows.test.tsx` runs shared nested-input workflows through legacy dot names, modern tuple names, and descriptors. Keep these integration checks alongside component tests: selection, numeric/date adapters, file reset, and ComboBox commit-before-submit can fail even when the store is correct. The React 18/19 and compiler matrices include this suite; native Enter and reset cancellation are also covered in Chromium.

`DialogForm` selects its backend by controller brand. `ModernDialogForm.tsx` uses the modern root's internal success callback so root and hook callbacks (including imperative submits) retain their precedence. Dismissal cancels pending submissions even with preserved drafts. Lifecycle tests in `modern/dialog.test.tsx` cover portal relocation, Strict Mode, hidden roots, and reopening; `dialog.fixture.tsx` and the modern dialog implementation run through React Compiler. Keep ordinary Storybook form examples modern and label dedicated legacy references explicitly.
