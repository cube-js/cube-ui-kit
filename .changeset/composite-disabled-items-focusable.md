Keyboard navigation now stops on a disabled item instead of skipping it, in every composite widget, as `Menu` and `CommandMenu` already do and as WAI-ARIA recommends, so a keyboard or screen reader user hears it, its description and that it is disabled. This covers `ListBox` and the fields built on it (`Picker`, `Select`, `ComboBox`, `FilterListBox`, `FilterPicker` in list and tree mode, `SearchComboBox`, `CommandTextArea`, `TagInput`'s options), `Tree`, `Tabs`, `ToggleGroup` (with or without a tooltip), `TagInput`'s locked chips, and `ItemTable` rows. The item stays disabled: `aria-disabled`, never selected, toggled, removed, expanded or activated, and Enter, Space and a click do nothing. A list that highlights an option on its own as you type still picks the first one you can choose, and a fully disabled field or group stays out of the keyboard. Two bugs are fixed along the way: the `Tabs` overflow picker listed a disabled tab as an option you could choose, which activated it, and in an `ItemTable` with tree rows the arrow keys moved focus onto the table itself when the next row was disabled. Tests that expected the arrow keys to skip a disabled item need updating.
