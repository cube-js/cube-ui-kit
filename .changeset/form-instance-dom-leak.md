Fix `PasswordInput`, `TextArea`, `CommandTextArea`, `Checkbox`, `CheckboxGroup`, `RadioGroup`, `ColorSwatchGroup`, `Switch` and `Select` rendering `form="[object Object]"` on their native inputs when bound to a `Form.useForm()` instance, whether through a surrounding `<Form>` or the `form` prop. React Aria writes `form` onto the input as the id of the `<form>` it belongs to, so the attribute named no form and detached the input from its own: pressing Enter in a `PasswordInput` submitted nothing. The form instance no longer reaches the DOM, so these inputs now behave inside a legacy form as they already did with `Form.useController()`: Enter in a `PasswordInput` submits the form, and Enter on a `Checkbox`, `Switch` or radio submits it when the form has a submit button. A native reset of a legacy form, such as `Form.ResetButton` or `formElement.reset()`, now resets the form once and reports the defaults to `onValuesChange`, as `Form.useController()` forms already did; before, React Aria wrote each input's starting value on its own (a `CheckboxGroup` could end up empty). On the text fields, a `form` id passed through `inputProps` still applies. `ColorSwatchGroup` also no longer throws when a native form reset clears a group that mounted with no value.
