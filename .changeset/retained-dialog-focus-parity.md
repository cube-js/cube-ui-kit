A `hideOnClose` dialog now moves focus as a dialog without it does in more cases. A `Button`, `ItemButton`, `ItemAction`, `Action`, `Select`, `Checkbox`, `Switch`, `Radio`, `CommandMenu`, `DateInput`, `TimeInput` or date picker with `autoFocus` takes focus on every open, as autofocused text fields already did: these controls now mark themselves `data-autofocus`, and a dialog's first focus goes to the last marked control that can take focus (a date field's first segment) before a submit or primary button. Closing a dialog opened from a menu item, or from a button in a popover, returns focus to that menu's or popover's trigger, and so does unmounting it while it is open. `Tab` past either end of a retained panel or of a popover that is not dismissable, and `Tab` from any retained dialog while it closes, moves to the controls beside its opener. A dialog opened from a retained one returns focus to that one's opener when it closes after it. A retained dialog nested in another overlay opens above it, where the browser supports `moveBefore`. And a retained dialog focuses itself on open, and again half a second later, as React Aria's `useDialog` does, waiting for transitions when a screen reader's virtual cursor opened it. A dialog without `hideOnClose` that a screen reader opens now also focuses its autofocused control, such as a danger `AlertDialog`'s Cancel, where it focused the primary button before. The DialogContainer docs list what still differs.
