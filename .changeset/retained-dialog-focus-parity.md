A `hideOnClose` dialog now moves focus as a dialog without it does in more cases. Autofocused buttons, selects, checkboxes, switches, radios, `CommandMenu` and date fields take focus on every open, as autofocused text fields already did, and the last of several autofocused controls wins. Closing a dialog opened from a menu item or from a button in a popover returns focus to that menu's or popover's trigger, and so does unmounting the dialog while it is open. `Tab` out of a retained panel, out of a popover that is not dismissable, or from any retained dialog while it closes moves to the controls beside its opener. A dialog opened from a retained one returns focus to that one's opener. A retained dialog nested in another overlay opens above it where the browser supports `moveBefore`, and it focuses itself on open and again half a second later, as `useDialog` does. Any dialog that a screen reader opens now focuses its autofocused control, its submit or primary button, or else the dialog itself, rather than its first control or a destructive button. A kit control's `data-autofocus` set by the consumer is no longer dropped. The DialogContainer docs list what still differs.
