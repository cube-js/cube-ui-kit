Add tree-shaped options to `FilterPicker`: pass `treeData` (with `expandedKeys`, `defaultExpandedKeys` and `onExpand`) and the popover shows a checkable `Tree` under the usual header, search and footer. Tree mode is always multiple selection. Its value is every fully checked key, parents included, in tree order: checking a parent checks its children, and a partly checked parent is half-checked. The cascade runs over the whole tree, so a search never unchecks the nodes it hides. A search keeps each match with its subtree and opens the ancestors of deeper matches, then restores the user's expansion when it clears. Focus stays in the search input, which drives the active row: arrows move it, Right and Left open and close it, Space toggles it while the search is empty, and Enter toggles it and closes the popover. The default summary lists the topmost checked nodes, and `renderSummary` receives every checked key in tree order. Nothing in the tree is a tab stop, so Tab moves from the search to the footer. `children` is now optional in `CubeFilterPickerProps`, since a tree-mode picker has none.

`Tree` changes that come with it: a node's new `textValue` names its checkbox when `title` is not a string, and a `Tree` with an `id` gives each row an id derived from it. In `defaultCheckedKeys` and the array form of `checkedKeys`, a parent key now checks its whole subtree, as in AntD; before, a parent listed without its children rendered unchecked. That holds for a parent whose own checkbox is disabled too. The object form `{ checked, halfChecked }` is taken as given, as before. Rows no longer carry `aria-checked`, which `role="row"` does not support (axe `aria-allowed-attr`); each row's checkbox still reports checked and mixed, and the row keeps its `data-checked` and `data-indeterminate` attributes, so a test that read the row's `aria-checked` should read one of those.
