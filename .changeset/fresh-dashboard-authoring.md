Add a standalone Dashboard compound component with a shared 12-column layout, transparent depth-aware container chrome, registered contextual add menus, independent tab layouts, surface and cross-container movement for widgets and containers, selected-group transfers with valid/danger drop previews, hard parent capacity for nested content, bounded resizing, and an interactive authoring Playground with atomic tree transfers.

Dashboard owns collision resolution: a proposal arrives with every placement it resolved — the grabbed group in `info.items`, the siblings it moved aside in `info.displaced`, and `info.isBlocked` when no resolution exists — so a consumer writes placements instead of reimplementing reflow. A pointer move now tries every container under the pointer from the deepest outward and lands in the first that can take the geometry, hit-tests against geometry snapshotted once per gesture, tracks true client coordinates so a mid-drag scroll cannot desynchronise it, and cancels on `Escape`.

Each node's actions sit behind one menu in its top-right corner: Settings, opt-in Duplicate, consumer-supplied `actions` dispatched through `onMenuAction`, seven size commands (each disabled when it would change nothing), and Delete. The size commands report through `onPlacementChange` with the new `'command'` input and are the accessible equivalent of the resize gesture. Node chrome is ordered in a single stacking context at the Dashboard root, so it stays reachable above every node body at every depth, and top-level containers are separated by a fixed `2x` channel.

A Grid's add button can be pressed and dragged — or grown with `Shift` and the arrow keys — to claim an area before choosing what fills it; the button occupies the claim and the menu then offers only items that can be that size.

A stack now fills itself: its children share its own axis in proportion to their stored spans and never below their own minimums, so resizing a stack stretches or squeezes what is inside it, and a stack's own bounds are the sums of its children's minimums and maximums rather than of their current spans. Drops and add-menu items are offered whenever the residents can be squeezed far enough to seat the newcomer's minimum, and a stack being authored gains a narrow track of its own to hold its insertion point. Resizing a child _of_ a stack is a seam rather than a claim: it takes tracks from the next neighbour and hands them back the same way, reported through `info.displaced`. Inside a stack an arrow key moves a node one position rather than one cell, which a packed sequence would otherwise swallow. A click that does not land on a node now clears the selection wherever it falls, not only on Dashboard whitespace, while a node's own menu is excluded so working through it never deselects the node.
