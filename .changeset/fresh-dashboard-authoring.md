Add a standalone Dashboard compound component with a shared 12-column layout, transparent depth-aware container chrome, registered contextual add menus, independent tab layouts, surface and cross-container movement for widgets and containers, selected-group transfers with valid/danger drop previews, hard parent capacity for nested content, bounded resizing, and an interactive authoring Playground with atomic tree transfers.

Dashboard owns collision resolution: a proposal arrives with every placement it resolved — the grabbed group in `info.items`, the siblings it moved aside in `info.displaced`, and `info.isBlocked` when no resolution exists — so a consumer writes placements instead of reimplementing reflow. A pointer move now tries every container under the pointer from the deepest outward and lands in the first that can take the geometry, hit-tests against geometry snapshotted once per gesture, and tracks true client coordinates so a mid-drag scroll cannot desynchronise it. A tab panel renders one layout container and nothing else, so it takes a single container and only while it is empty. `Escape` cancels a move or a resize by reporting the arrangement the gesture started from as its `commit` — the node through `info.items`, every sibling the previews had shuffled through `info.displaced` — so a consumer that applies previews applies the commit too rather than treating it as a repeat.

Each node's actions sit behind one menu in its top-right corner: Settings, opt-in Duplicate, consumer-supplied `actions` dispatched through `onMenuAction`, seven size commands (each disabled when it would change nothing), and Delete. The size commands report through `onPlacementChange` with the new `'command'` input and are the accessible equivalent of the resize gesture. Node chrome is ordered in a single stacking context at the Dashboard root, so it stays reachable above every node body at every depth, and top-level containers are separated by a fixed `2x` channel.

A Grid's add button can be pressed and dragged — or grown with `Shift` and the arrow keys — to claim an area before choosing what fills it; the button occupies the claim and the menu then offers only items that can be that size.

Resizing a stack now carries its children with it. Its bounds are the sums of its children's minimums and maximums, so it can be narrowed until they reach their floors and widened until they run out of room to take, and Dashboard reports every child's new span in `info.displaced` alongside the stack's own placement — one level below the reported parent, so a consumer writes them by id. Nothing else moves a stack child's span: resizing one child grows it into the room its siblings left over and shrinks it to its own minimum, leaving every sibling where it was, and a child that can do neither exposes no resize grip. Inside a stack an arrow key moves a node one position rather than one cell, which a packed sequence would otherwise swallow. A stack derives its children's coordinates from their order and ignores any the consumer stored, since a stack lays out by span alone and there is nothing there for a consumer to maintain. A click that does not land on a node now clears the selection wherever it falls, not only on Dashboard whitespace, while a node's own menu is excluded so working through it never deselects the node. `Space` selects the focused node with the same modifiers a click takes.
