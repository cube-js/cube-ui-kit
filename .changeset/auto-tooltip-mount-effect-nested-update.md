Stop `useAutoTooltip` from setting its overflow verdict inside the mount effect. React 19 flushes a sync commit's passive effects before the commit returns, so an overflowing `Button`, `Item`, `TextItem`, `LayoutHeader` or `InlineInput` label left every commit it mounted in with an update pending, which React counts as a nested update. A list that commits each row on its own — ag-grid-react 33 wraps every new row in `flushSync` — therefore crashed with "Maximum update depth exceeded" once about 50 such rows mounted in one task, for example when a long table jumped back to its top. The effect now queues the same microtask the callback ref already uses, so the verdict still lands after the commit and before paint, without a second layout read. A test that renders inside a synchronous `act()` no longer finds the verdict applied when `render` returns: `await act(async () => …)` first, then look the label up, since turning the tooltip on remounts it under `TooltipProvider`.
