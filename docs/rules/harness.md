# Harness for Coding Agents — `harness/`

`harness/` ships in the package for projects that use [harnesspm](https://www.npmjs.com/package/@tenphi/harnesspm). It is for agents that **use** UI Kit; the rules for working on UI Kit stay in [`AGENTS.md`](../../AGENTS.md) and `docs/rules/`. This repository uses harnesspm too, so the block at the end of `AGENTS.md` lists the same harness, changed for this repository by `harnesspm.json`. Since harnesspm 0.8.0 the block names each always-on rule in one line, and `npx -y @tenphi/harnesspm help <package>` prints the rules in full.

- [`plugin.json`](../../harness/plugin.json) extends `@tenphi/glaze` and `@tenphi/tasty`, so a project gets Glaze's colors rule, docs and `glaze-theme` skill, and Tasty's styles rule and docs, through UI Kit. It also extends `@tenphi/eslint-plugin-tasty`, an optional peer: a project that installs the plugin gets its `tasty-lint` harness (a rule to lint changed styles, a page for every `tasty/*` rule, `tasty-lint:check`, and a hook that lints each file an agent edits), and harnesspm skips it quietly in a project without the plugin. Every `extends` entry must be a dependency or an optional peer, which `src/harness.test.ts` checks. Scripts run only in projects that trust their package: `uikit:colors` needs `@cube-dev/ui-kit` trusted, Glaze's `glaze:*` tools need `@tenphi/glaze`, `tasty:styles` needs `@tenphi/tasty`, and `tasty-lint:check` and its edit hook need `@tenphi/eslint-plugin-tasty`. Its `docs` is `docs/`, which [`scripts/prepare-docs.mjs`](../../scripts/prepare-docs.mjs) builds at `prepack` and removes at `postpack` (`--clean`). Each Storybook page (`src/**/*.docs.mdx`) and Modern Form guide becomes plain Markdown at a short path, such as `docs/components/actions/Button.md`, with its links rewritten to work in the package, and `docs/llms.txt` indexes them, so harnesspm uses it as `uikit:docs`. A link that leads nowhere fails the build, so the pack and the canary fail too. Tasty's and Glaze's indexes come with their harnesses. To read the built docs here, run `node scripts/prepare-docs.mjs`, and `--clean` after.
- [`rules/usage.md`](../../harness/dev.harnesspm/rules/usage.md) (`uikit:rules/usage`) is the one always-on rule, with UI Kit's color guidance and a pointer to the Usage guide's typography preset tables. Keep that pointer in its own `## Typography` section: Cube Cloud's patch replaces `## Styling`, so a bullet added there doesn't reach Cloud's agents. UI Kit's own `harnesspm/patches/uikit-usage.patch.md` replaces all three sections for this repository, with `src/` in place of the docs index and `pnpm probe` in place of `uikit:colors`, so a change to one of them goes into that patch too. Keep it short: harnesspm 0.6 and 0.7 inline it in every consumer's `AGENTS.md`. From 0.8.0 the block carries only its title and `##` headings ("UI Kit — Components, Styling, Typography"), so a heading must say what its section covers; renaming one also breaks every patch that replaces that section. Its ID is public, since consumers name it to patch or exclude it.
- [`patches/glaze-colors.patch.md`](../../harness/dev.harnesspm/patches/glaze-colors.patch.md) replaces only the "Where colors come from" section of Glaze's colors rule, which would otherwise send an app on UI Kit to a Glaze theme of its own.
- [`patches/tasty-usage.patch.md`](../../harness/dev.harnesspm/patches/tasty-usage.patch.md) replaces only the "Checking styles" section of Tasty's rule, so `tasty:styles` loads UI Kit's `configure()` through `--setup @cube-dev/ui-kit/dist/components/Root.js`. Without it, the CSS uses Tasty's default units and none of UI Kit's states or recipes.
- `uikit:colors` ([`scripts/colors.mjs`](../../harness/dev.harnesspm/scripts/colors.mjs)) is for consumers: palette tokens and their aliases by their Tasty names (which aliases are legacy is the Usage guide's call, not the tool's), with values in all four schemes and contrast against their base, or with `--on <token>` on another surface, held to the token's own floor, measured by Glaze's public measuring module, `@tenphi/glaze/harness/measure`, from the pinned Glaze. It reads `dist/`. While you edit the palette here, use `pnpm probe tokens`, which reads `src/`. Its `usage` in `plugin.json`, which `npx -y @tenphi/harnesspm help uikit:colors` prints (harnesspm 0.8.0 and later), lists the arguments and options `main()` parses: change the two together.
- [`harnesspm.json`](../../harnesspm.json) changes the harness for this repository only, never for consumers. It trusts `@tenphi/tasty`, `@tenphi/glaze` and `@tenphi/eslint-plugin-tasty`, so their tools and the lint hook run here. Its patches in `harnesspm/patches/` point the UI Kit, Tasty and Glaze rules at `src/` and `pnpm probe`, because the shipped text names the docs index, `dist/` and a consumer's own Glaze theme, and keep UI Kit's `oxlint-disable-next-line` spelling in the lint rule. It excludes `uikit:docs`: here `docs/` holds only `docs/rules/` until a pack, and agents read the pages in `src/`. So the lock doesn't change when a page does.
- `pnpm install` runs `harnesspm sync` (in `prepare`); `pnpm add` does not. After `pnpm add` or a change to `harness/` or `harnesspm.json`, run `pnpm exec harnesspm sync` and commit `AGENTS.md` and `harnesspm.lock.json`. The lint job runs `pnpm exec harnesspm sync --check`, which fails when they are out of date: with `CI=true`, the install's sync leaves committed files alone. harnesspm also keeps a `CLAUDE.md` with `@AGENTS.md` next to every nested `AGENTS.md`, so Claude Code reads them; don't remove those imports.
- `pnpm check:harness` (`harnesspm check`, a devDependency) validates the harness, and CI runs it in the lint job. [`src/harness.test.ts`](../../src/harness.test.ts) guards what it cannot see: the packages `extends` names, the Glaze and Tasty sections the patches replace, and the tool; `package-tests/artifacts.test.tsx` runs the tool, checks the built `docs/` (plain Markdown, every page in `llms.txt`, no `src/`), runs `harnesspm check` on the extracted package, where no `.gitignore` hides the built docs from it, and runs `tasty:styles` with the setup the Tasty patch names, all on the packed build. `scripts/prepare-docs.test.mjs` builds every page in memory, so `pnpm test` reports a dead link before a pack does.
